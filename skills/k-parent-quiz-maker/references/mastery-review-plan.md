# 숙달·복습 설계 (mastery-review-plan)

`k-parent-quiz-maker`의 다음 단계 설계 개념. DeepTutor(HKUDS, Apache-2.0)의 문항 은행·숙달
게이트·예정된 반복 구조를 이 저장소의 가드레일에 맞게 다시 쓴 것이다. 아이디어 참고이며 원본
코드·문장은 복제하지 않았다. 출처: https://github.com/HKUDS/DeepTutor (2026-10-28 확인,
`docs/research/deeptutor-idea-integration-2026-10-28.md` 참고).

## 설계 원칙

1. **결정적 문항 유지**: 모든 문항은 `packages/k-parent-quiz-core`의 성취기준 템플릿과 seed로
   생성한다. LLM 자유 생성 문항은 추가하지 않는다.
2. **식별 없는 상태**: 복습 상태는 성취기준 코드 + 문항 seed + 다음 복습 시점만 저장한다. 아이
   이름, 학습 원문, 대화 기록은 저장하지 않는다(메모리 정책 준수).
3. **평가가 아니라 추천**: 숙달 상태는 "무엇을 언제 다시 보면 좋은지"를 위한 신호일 뿐, 성적·비교
   표현으로 쓰지 않는다.

## 구성 요소

### 1. 문항 은행 (이미 존재, 확장)

- `generate-quiz-bank.mjs`가 성취기준당 유형별 최대 3변형을 재현 가능하게 뽑아낸다.
- 확장: 은행 항목에 `difficultyBand`(하·중·상)를 부여한다. `k12-lesson-differentiation` 개작
  시안과 같은 3단계 구분을 문항 메타데이터 수준에서만 추가한다.

### 2. 오답 추적 (심플 대체재)

DeepTutor는 학습자 계정 아래 오답을 저장한다. 우리는 대신 **성취기준 코드 단위의 카운터**만
클라이언트 로컬에 둔다.

```text
state = { "<성취기준코드>": { "miss": 2, "lastSeed": 8123, "nextReview": "2026-10-30" } }
```

- 대화 원문, 오답 보기, 아이 반응은 저장하지 않는다.
- 저장 위치는 앱 로컬(`apps/k-parent-quiz-app`) 또는 기기 로컬만. 서버 메모리에 올리지 않는다.

### 3. 숙달 게이트

- 성취기준(또는 문항 유형)별로 "연속 2회 정답 → 복습 주기 연장" 정도의 단순 규칙만 둔다.
  (연속 2회 정답: 1일 → 3일 → 7일 간격)
- DeepTutor의 강한 per-type 게이트·대시보드는 도입하지 않는다. 부모에게 받는 신호는
  "이번 주에 다시 볼 만한 과목·단원 후보" 한 줄이면 충분하다.

### 4. 예정된 반복 연결

- 복습 후보가 잡히면 기존 출력 형식의 "부모의 다음 행동(재퀴즈 시점)" 칸에 반영한다.
- 캘린더 후보 생성은 `k-parent-schedule-manager`의 HITL 경로를 따른다(자동 등록 금지).

## 명시적으로 하지 않는 것

- 학습자 계정, 서버 측 학습 데이터 저장, 반별·또래 비교
- DeepTutor식 LLM 생성 문항, 자유 서술형 채점
- 숙달 대시보드 제품 표면 (필요성이 확인되면 별도 기능 문서로 제안)

## 단계

1. `k-parent-quiz-core`에 난이도 밴드 부여 방식 정의 (변형 템플릿 파라미터로)
2. 앱 로컬 상태 스키마 확정 후 `apps/k-parent-quiz-app` 결과 화면에 "다음 복습 후보" 표시
3. 반복 사용 패턴이 확인되면 이 문서를 기능 문서로 승격
